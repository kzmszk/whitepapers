# 白書から、経産省が変えようとしていることを読む

調査・収集日：2026年9月22日。対象：通商、ものづくり、中小企業・小規模企業、エネルギー。

## 提案

**政府の課題認識と対応の理由を入口にし、暮らしとの関係と根拠のデータへつなぐ。** 読者が「何を心配し、なぜその対応を選び、何を変えたいのか」を理解できることを主目的にする。統計の操作は、その説明を確かめ、自分の問いを調べるために用意する。

トップは「横断した全体像 → 5冊の問題意識 → 暮らしにつながる記事 → 成果を確かめる指標 → データ比較」の順にする。記事は「課題の認識 → 対応の理由 → 具体策 → 暮らしとの関係 → 成果を確かめる指標 → 自分で分析」を共通の型にする。白書の章立ては出典の索引として残す。画面ごとの役割、図解、記述と根拠の結び方は[改訂したサイト構成](SITE-STRUCTURE.md)を参照。

今回確認した白書・担当部局の解説を横断すると、**供給網、人手、エネルギー等の制約に備えつつ、投資・技術・経営の改善で国内の稼ぐ力と賃上げを支えたい**という方向で整理できる。これは本企画の編集上の要約であり、政府が掲げた一つの標語ではない。

| 政策上の方向 | 根拠 | 読者への入口 |
|---|---|---|
| 海外との取引を広げながら、供給の途絶に備える | [通商白書2026の経産省解説、p.55–57](https://www.rieti.go.jp/jp/events/bbl/26072301_yoda.pdf#page=55) | 「取引先が偏ると、何が困る？」 |
| 投資・データ活用・人材育成で製造業の競争力を高める | [ものづくり白書2026・国会提出概要](https://www.shugiin.go.jp/internet/itdb_gian.nsf/html/gian/gian_hokoku/20260529monogaiyo.pdf/%24File/20260529monogaiyo.pdf) | 「人手が減るなかで、どう作り続ける？」 |
| 付加価値と生産性を高め、賃上げを続けられる経営へ進む | [中小企業庁調査室長の2026年版説明、p.3–5・9–17](https://www.rieti.go.jp/jp/events/bbl/26061101_okada.pdf#page=3) | 「給料を上げ続けるには、何が必要？」 |
| 安全を前提に、安定供給・経済性・環境を一緒に考える | [エネルギー白書2025・第2部はじめに](https://www.enecho.meti.go.jp/about/whitepaper/2025/html/2-0-0.html) | 「安く、安定して、排出も少ない電気はどう作る？」 |

ものづくり白書は経産省・厚労省・文科省の共同作成。雇用・訓練や教育の主張をすべて経産省単独の考えとして紹介せず、担当を表示する。政策の目的と、政策の効果が実証されたことも区別する。

地域別電源・送電網や福島復興の詳細年表、AI導入の個票分析、白書の年次比較は、上の5記事とは別の拡張候補。図解案を実装済みのデータとして数えない。

一画面に複数の結論を詰め込まず、一つの問いに一つの主要グラフを対応させる。長い凡例や専門語は、図の中に直接ラベルを置き、短い補足と詳細説明へ分ける。色だけに頼らず、線種・ラベル・表を併用する。棒グラフは原則ゼロから、時系列では対象期間・軸の範囲を明示する。

読みやすさは、図を増やすことだけでは解決しない。スマートフォンで読める文字、同じ尺度で比べられる図、説明と図の近さ、原本への短い経路を優先する。

## 操作試作で確かめたこと

[ローカル試作](http://127.0.0.1:8765/)は、政策の全体像と5冊の要約を入口とし、5テーマの解説と実データ比較へつなぐ。説明は「白書の説明」「公式統計から再集計」「このサイトの整理」で区別する。比較は財務省の「鉱物性燃料輸入額」と総務省の「エネルギーCPI」を使用する。期間変更、系列の追加・除外、開始年を100にする表示、前年比表示、数値表、表示データのCSV保存、計算条件JSON保存を用意した。

取得原本から独立に再計算すると、2020年を100とした2025年の値は、燃料輸入額**196.8**、エネルギーCPI**123.0**。2025年の前年比は、それぞれ**−13.2%**と**＋3.6%**だった。出典は[財務省の年別主要商品輸入CSV](https://www.customs.go.jp/toukei/suii/html/data/d61ca.csv)と[総務省の2020年基準CPI月次CSV](https://www.stat.go.jp/data/cpi/2020/csv/zmi2020aa.csv)。CPIは12か月の指数から年平均を計算している。

これは「同じ指標なのに結果が違う」という話ではない。輸入額は価格・為替・数量などを含む名目金額、CPIは家計の購入価格指数である。両者の違いそのものを、データの読み方として説明できる。輸入額だけから家庭の支払額や政策効果は推定しない。

保存するCSVには、表示用数値だけでなく、丸め前の値、元の値・単位、出典URL、取得日時、原本ハッシュを含める。条件JSONには系列・品目コード・期間・式・集計方法を含める。「画像を保存」だけで終わらせず、利用者自身の検証に戻れる形にする。

## データを自由に扱える範囲

「元データ」を一種類として扱わない。

1. **白書の図表画像**：読むための資料。値の再集計には適さない。
2. **白書の図表Excel**：掲載図の再描画に向く。元調査の全項目や個票があるとは限らない。
3. **出典統計の公表集計表**：今回主に取得したもの。業種、期間、品目等の公開されている分類で再集計できる。
4. **調査票の個票・民間調査データ**：今回取得していない。企業属性の任意の組合せや独自回帰分析が自由にできるとは約束しない。

公開集計表でも、調査年と実績年、企業規模の定義、分類の包含関係、暦年と年度、指数の基準改定を保持する。中小企業実態基本調査の `－`、`0`、`…`、`x` はそれぞれ意味が違い、一括でゼロに置き換えない。

実際に見つかった設計上の注意は次のとおり。

- **賃金**：取得した厚労省表では2024年の名目賃金指数が109.2、2023年が103.5なのに、公表前年比は2.8%。ベンチマーク更新の影響を取り除いた比較なので、単純比の約5.5%を公式賃金上昇率として表示しない。[利用上の注意9、原PDF](https://www.mhlw.go.jp/toukei/itiran/roudou/monthly/r07/2512r/dl/pdf2512r.pdf)
- **エネルギー自給率**：高位発熱量の本表で国内産出を供給で割った約19.7%を、公式IEAベースの2024年度16.3%と同じものとして扱わない。定義と取得版を一致させる。詳細は[エネルギー調査](energy.md)。
- **鉱工業指数**：「付加価値額生産」は付加価値額で重み付けした生産数量指数であり、企業の名目付加価値額そのものではない。
- **期間**：エネルギーの年度統計と、貿易の暦年合計を年ラベルだけで結合しない。必要なら月次原表から同じ年度に再集計する。

## 図版の使い方

今回保存した7枚は、公式資料の出典・脚注も含めて確認するための参照画像。第三者の図、RIETIや国会掲載資料等の条件をまとめて「自由に公開可能」とは判断していない。

公開画面では、数値から描き直したグラフと、自作の工場・店舗・家庭・供給網の模式図を主に使う。写真が必要な記事だけ、個別に条件を確認した素材を追加する。参照画像は原文の構成や注記を確認するために利用し、現状の公開用フォルダには入れていない。

[経産省利用規約](https://www.meti.go.jp/main/rules.html)、[第三者権利に関する別紙](https://www.meti.go.jp/main/rules_02.html)、[e-Stat利用規約](https://www.e-stat.go.jp/terms-of-use)を出典台帳に持つ。加工した図には「出典○○を加工して作成」と記載し、省庁の公式サイト・監修済みサイトと誤認されないようにする。

## Cloudflare Workersへの実装順

詳しい境界・データモデル・制約は[構成設計](ARCHITECTURE.md)にまとめた。

1. **最初の公開単位**：政策の全体像、5冊の要約、5テーマの記事とおすすめ比較、出典・CSV・計算条件保存。ここまでローカル実装済み。各記事は課題と対応を図解し、成果を確認する指標と限界を示す。静的記事と整形済みJSON/CSVをWorkers Static Assetsで配信する。
2. **データの充実**：業種・品目・地域の選択を増やす。大きい原本・Parquet等は公開条件を確認してR2へ置く。原本→正規化→表示の版を固定する。
3. **分析の拡張**：保存した条件の再読込・共有、異なる頻度の集計、構成比、検証済みの結合レシピを追加する。必要になった時点でD1やDuckDB-Wasmを検討する。
4. **更新運用**：公表日・改定を検知し、差分と図を確認してから公開版を切り替える。速報から確報への置換で、過去に保存した図が再現不能にならないようにする。

複雑なExcel・PDF処理を毎回Worker上で行うより、手元またはCIで処理した小さなデータを配信する構成が適する。Workersの実行メモリは128 MB、静的アセットは1ファイル25 MiBの制限がある。[公式の実行制限](https://developers.cloudflare.com/workers/platform/limits/)、[静的アセットの制限](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)
