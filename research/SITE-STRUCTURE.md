# 経産省は、何を変えようとしているのか

構成改訂：2026-09-22。対象読者は政策・統計の専門知識を持たない一般読者。経産省と関係省庁が公表した課題認識と対応の理由を理解し、その根拠を自分でも確かめられるサイトにする。

## 編集の中心

**課題の認識 → 対応の理由 → 具体策 → 暮らしとの関係 → 成果を確かめる指標 → 自分で分析**を記事の共通の型にする。グラフは、その段階で読者が抱く疑問を説明する場所に置く。

通商白書の担当局は、作成目的として、国際経済・諸外国の政策の分析を通じた政策形成への貢献と、国民に対する政策の考え方・方向性の提示を挙げている。[担当局説明資料、PDF2頁](https://www.rieti.go.jp/jp/events/bbl/26072301_yoda.pdf#page=2)。この目的をサイトの入口に据える。

構成の選択肢は三つ比較した。白書別の目次は原文参照に便利だが、分野のつながりが見えにくい。暮らしの質問だけを並べる構成は親しみやすいが、政府が何を重視するかが伝わりにくい。**最初に政策の全体像を示し、白書別の要約と暮らしの記事から深掘りする構成**を採る。データ操作は記事の根拠を調べる入口と、直接使える分析室の両方に残す。

本番のURL候補は `/`、`/whitepapers/:id`、`/themes/:id`、`/explore`、`/sources/:id`。今回の構成試作は1ページのアンカーと折りたたみで読み順を検証する。未実装のページへのリンクは置かない。

## トップの読み順

1. **何を変えようとしているのか。** 見出しと、横断して読める共通の方向を一文で示す。主ボタンは「白書の考え方を読む」。分析室への直行はメインナビに残す。
2. **5冊の白書、それぞれの問題意識。** 要点は常に見え、開くと課題・対応・原文へ進める。中小企業と小規模企業は別々に扱う。
3. **暮らしとつなげて読む。** 五つの問いを示す。今回の記事試作はエネルギー。他の項目は白書別要約へ進み、完成した詳細記事があると誤認させない。
4. **記事試作：電気を安定して、無理のない価格で使い続けるには。** 課題と対応を図解してから、燃料輸入額とエネルギーCPIの比較へ進む。
5. **自分で確かめる。** 指標を操作し、表・CSV・計算条件・出典に到達する。「この比較で分かる範囲」と「政策成果を測るためにさらに必要な指標」を添える。

## 記事の型と図の役割

| 順序 | 記事が答える問い | エネルギー記事の例 | 図・データ |
|---|---|---|---|
| 1 | 政府は何を心配しているか | 輸入燃料への依存、供給と価格の不安定さ、今後の電力需要 | 資源→産業→家庭の自作模式図。数量に比例した図とは扱わない |
| 2 | なぜその対応が必要と考えるか | 安定供給・経済性・環境を、安全を前提に一緒に考える | 安全を土台に三つの目的を並べる図 |
| 3 | 何をしようとしているか | 省エネ、再エネ・原子力等の活用、電源と産業立地の連携 | 具体策と狙いを対応させた短い説明 |
| 4 | 生活や仕事とどう関係するか | 電気料金、操業の安定、設備投資、仕事への関係 | 経路の説明。料金引下げ等を確定した結果として描かない |
| 5 | 何を一緒に判断する必要があるか | 費用、安全、排出、供給の安定性 | 項目ごとの説明。根拠のない総合点・電源ランキングを作らない |
| 6 | 目標に近づいたか、何で確かめるか | 自給率・調達先、価格・実支出、排出量等をそれぞれ確認 | 掲載済み・データ整備中を明示。推移と政策の因果効果は区別 |
| 7 | 自分ではどう調べられるか | 燃料輸入額と家庭の価格を期間・系列を変えて比較 | 既存の実データ比較。出典、定義、CSV、計算条件 |

エネルギー記事の政策根拠は2025年白書、比較データの取得版は2026-09-22。比較は白書掲載図の再現でも、政策効果の実証でもないことを、グラフに入る前に示す。

## 記述と根拠の結び方

「白書の説明」「公式統計から再集計」「このサイトの整理」を文字で区別する。色だけを区別の手段にしない。政策の構想、実施済みの施策、将来目標、観測済みの結果も区別する。

各論点は `id / kind / summary / issuer / edition / source_url / locator / source_type / verification_status` を持つ。`kind` は課題認識・対応理由・施策・目標・観測・編集上の解釈のいずれか。`source_type` は白書本文・公式概要・担当官説明・原統計。統計への関連付けには `supports / context / outcome_indicator_candidate` を使い、比較に使える系列が政策効果を証明する系列だとは扱わない。

今回、本文の説明と出典は静的HTMLが所有し、比較データと計算処理は既存のJSON・JavaScriptが所有する。CMS・D1のスキーマはこの概念を基に本番実装時に確定する。閲覧のたびに文章を生成する構成にはしない。

## 実装の順序と今回の確認範囲

今回：トップ、5冊の要約、エネルギーの記事試作、既存比較への接続、出典表示を更新する。PC・スマートフォンで入口から原文・比較へ進めるか、折りたたみとキーボード操作、グラフの期間・系列変更を確認する。

次：賃上げ、ものづくり、供給網、地域の事業を同じ型で記事化する。年次比較の記事は複数年の本文を照合してから追加する。成果指標の追加は定義・期間・掲載時点を確認して実装する。

Cloudflare Workersの前提は維持する。記事・図はStatic Assets、公開する原本はR2、検索・集計・保存する分析条件は必要な段階でD1へ置く。今回の変更は公開前のローカル試作であり、ストレージ接続や本番公開を含まない。
