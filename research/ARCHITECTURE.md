# データを確かめながら読むための設計

## 読者の操作から決める

記事を読み、「このグラフを動かす」を押すと、その記事と同じ系列・期間の比較画面を開く。系列を追加し、期間と表示方法を変更し、表示中の表・CSV・計算条件を持ち帰れる。初回はログイン不要とする。

画面は「政策の全体像」「白書から読む」「暮らしから読む」「データで確かめる」「出典・読み方」で構成する。詳細は[SITE-STRUCTURE.md](SITE-STRUCTURE.md)。グラフをクリックできない読者にも、同じ情報を文章とHTML表で提供する。政策の解説を読むだけなら統計用語を理解している必要はない。

## データの形

原本、統計系列、白書の論点、図、読者の分析条件を分ける。

| 実体 | 必須情報 |
|---|---|
| SourceAsset | 出版者、公式URL、取得日時、原本パス、SHA-256、形式、取得状態、利用条件、公開可否 |
| DatasetVersion | 統計名、表ID、取得版、基準改定、公開日、白書掲載時点との関係、変換スクリプト |
| Series | 指標ID、対象地域、業種・企業規模、単位、暦年／年度、頻度、季節調整、名目／実質、集計方法、出典ID |
| Observation | 系列ID、期間、数値またはnull、欠測理由、速報／確報／改定等の状態 |
| Claim | ID、課題認識／対応理由／施策／目標／観測／編集上の解釈の種別、要約、所管、白書名・版・章節・ページ、出典URL、白書本文／公式概要／担当官説明／原統計の別、確認状態 |
| ClaimEvidence | 論点ID、出典または系列の版ID、関係（根拠／背景情報／成果確認指標の候補）。背景の比較系列を政策効果の証拠として扱わない |
| Recipe | 使用する系列版、期間、変換式、基準年、結合方法、欠測処理、レシピの版 |

同じ年・同じ指標名だけで結合しない。キーは地域・期間種別・頻度・必要な対象分類を含める。省庁や統計間の業種分類は対応表と適用年を保存する。系列の単位変換は明示したルールだけで行う。

## 比較と再集計のルール

- 暦年は1〜12月、年度はその定義を持たせ、選択時に区別する。年度値を年ラベルだけで暦年値と結合しない。
- フロー（金額・数量）は合計、価格・指数は出典に合う平均、ストックは期末など、系列ごとに集計方法を持つ。年度値しかないものを月次へ水増ししない。
- 指数化は `100 × 当期値 / 基準期値`。基準期が欠測またはゼロなら計算しない。異なる単位を比べるときは指数か各系列の別図を使い、恣意的な二重軸を標準にしない。
- 前年比は `100 × (当期値 / 前期値 - 1)`。調査設計変更等により公式の増減率と指数値からの単純計算が一致しない系列は、公式増減率を別の指標として保持する。
- 欠測をゼロや直前値で埋めない。線を切り、表とCSVに欠測理由を残す。合計・平均に必要な期間が不足したら部分期間として区別する。
- 構成比は分母・包含関係を確認してから計算する。品目の足し合わせで総合指数を再現する場合は、公式のウエイトと算式を使う。
- 金額の上昇を数量の増加と呼ばない。並行した動きを政策効果や因果関係と呼ばない。
- 白書時点の図を再現する版と、その後の改定を含む最新版を切り替えられる設計にする。原本を上書きしない。

## 配信方式の比較

| 案 | 良い点 | 負担 | 判断 |
|---|---|---|---|
| 整形済みの小さいJSON/CSVを配信し、ブラウザで比較 | 速く、再計算が見える。運用が簡単 | 大きな原表を丸ごと扱う用途には向かない | 初期版に採用 |
| Workerが要求のたびに外部統計・Excelを取得して集計 | 常に更新できるように見える | 取得先の停止、形式変更、実行制限が読者に直撃。白書の過去版も再現しにくい | 採用しない |
| R2上のParquetをDuckDB-Wasmで分析 | 詳細分類の探索に拡張できる | モバイルのメモリ、初期ロード、操作設計の負担 | 大きな表が必要になってから追加 |

## Cloudflare Workersでの構成案

```text
公式PDF / Excel / CSV / API
          │ 取得・ハッシュ・出典確認
          ▼
Pythonの収集／整形処理（手元またはCI）
          │ 定義照合・件数照合・図表との数値照合
          ▼
版を固定したJSON・CSV・必要に応じParquet
          ├── Workers Static Assets：記事・SVG・少量のデータ
          └── R2：公開条件を確認済みの大きな原本・データ
                       │
                       ▼
            ブラウザ：描画・期間変更・再計算・CSV出力
```

初期版は静的記事と小さな比較データで成立する。Worker側のAPIは必要になったところから追加する。検索・版管理は初期はJSON索引で足りる。共有レシピの永続保存などが必要になった段階でD1を導入する。更新検知をCron Triggerで行う場合も、大きなExcel/PDFの解析はCI等のバッチ処理へ回す。

WorkersはHTML・CSS・画像などの静的アセットを配信できる。静的ファイルの上限は1ファイル25 MiB、Workerのメモリは128 MB。大きな白書PDFをアセットに混ぜたり、リクエストのたびに展開したりしない設計にする。[Static Assets](https://developers.cloudflare.com/workers/static-assets/)、[制約](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)、[実行制限](https://developers.cloudflare.com/workers/platform/limits/)。仕様確認日：2026-09-22。

R2を配信に用いる場合は公開許可したオブジェクトだけを公開し、出典不明・第三者画像・ライセンス確認前の資料は配信対象から外す。キャッシュを利用する公開配信にはカスタムドメインを使う。[R2公式文書](https://developers.cloudflare.com/r2/buckets/public-buckets/)

## 再現・更新・公開

1. 公式ページの版・公表日とデータリンクを確認し、取得結果を台帳に記録する。
2. 原本を保存し、形式・ハッシュ・表内タイトルを検査する。HTTP成功でもHTMLのエラーページなら不採用。
3. 変換スクリプトで整形し、単位・年度・基準・欠測・改定を確認する。
4. 代表値を公式表と照合し、前版との差分をレビューする。失敗時は公開中の版を維持する。
5. グラフ・説明文・出典を同じ版として公開する。データのみ無断で最新版に置き換えない。

e-StatのAPIにはアプリケーションIDが必要。初期調査では公開CSV/Excelを使い、APIを採用するときはIDを配信HTMLに埋めず収集環境で管理する。[e-Stat利用ガイド](https://www.e-stat.go.jp/api/api-info/api-guide)

## 初期版の受け入れ条件

- 記事の主要な説明が白書の章節またはページまでたどれる。
- トップから課題・対応の理由・暮らしとの関係を読める。政府の説明、統計の観察、サイトの解釈を文字で区別する。
- 全グラフで単位・期間・出典・加工内容・取得版が分かる。
- 表示中のCSVと画面の数値が一致し、レシピから再現できる。
- 年度違い・単位違い・欠測を黙って補正しない。
- スマートフォン、キーボード、200%文字拡大で読む・比較する・出典を見る操作ができる。
- 低速回線でも記事本文と主要図が先に読める。グラフだけに重要な情報を閉じ込めない。
- 関係省庁が運営する公式サイトと誤認されない表示とする。

`content/*.json` に本文・種別・出典・図の定義をまとめ、専用の原表集計処理5本と `build_articles.py` で `prototype/themes/` と `prototype/data/` を作る。生成時に原本SHA・出典ID・観測値・期間・単位を検査する。共通の `article.js` は系列と期間の選択・指数化・数値表・CSV・レシピ保存を担当する。レシピには原数値のスナップショットと出典版を含める。保存は端末へのファイル出力のみで、サーバーの永続保存はない。
